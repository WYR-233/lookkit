# 设计决定

记下几个「当时为什么这么选」，免得以后自己（或别人）觉得奇怪又改回去。

## 1. 段与段用文件交接，不用函数调用

流水线五个阶段：scan → sheet → annotate → audit/review → export。

**选文件**：每段只读上一段的文件、写自己的文件。可以单独重跑任一段；模型或人可以直接用编辑器改中间产物；
断在哪儿都不丢进度。

**不选函数调用**：一个跑几小时的流程，中间挂一次要全部重来；而且「模型看 sheet 写 JSONL」这一步本来
就不是函数能封装的——它是让一个 agent 去干活。

## 2. `img/` 用 Python，其他用 Node

动图抽帧要：均匀采样、透明通道合成到背景色、逐帧时长累加、按格排版。Pillow 十几行就稳，
换成 imagemagick 命令行要做同样的事，代码更长、输出还容易变。

**输出绝不能轻易变**：prompt 里通常写着「浅灰 = 透明背景」「帧号在左上角」这类视觉约定。
拼图重写一遍、输出色值差一点，prompt 就在骗模型——这种 bug 极难发现，因为现象是"标签莫名其妙不准"。

所以：`img/` 固定 Python + Pillow，其余全 Node（内置模块，零第三方依赖）。

## 3. profile 用 JSON，不用 YAML

零依赖就能两边读（Node `JSON.parse`、Python `json.load`）。YAML 要引第三方库，或者手写一个不靠谱的解析器，
不值。注释靠旁边的文档和字段名本身。

## 4. 枚举必须有 fallback

模型写枚举时偶尔会造词（"有点小开心"）。有 `fallback` 就自动落回「其他」，
没 `fallback` 就整条数据脏掉，而脏数据在几百条里根本看不出来。

## 5. 派生状态（derived）不判死活

真实例子：一个检查项没过，可能是**画错了**，也可能是**构图没拍到**。这两件事的处理方式不一样——
后者不该算质量事故。所以 `checks[].derived` 允许「note 命中某模式时，单独标一个状态」。

同理，某一批本来就该表现别的样子（比如表情批本来就是各种表情），不该按同一把尺子判。

**规则写在 profile 里，不写在代码里。** 换个数据集就有不同的尺子。

## 6. 私货和引擎物理隔离

不是靠「记得别提交」，是靠三条硬约束：

1. `.gitignore` 从第一次 commit 之前就忽略 `legacy/`、`work/`、`data/`、所有图片和 db。
2. 私有场景档案放仓库外（`$LOOKKIT_PROFILES`），仓库里的 `profiles/` 只放中性示例。
3. `tools/check-private.sh` 在推送前扫一遍，抓署名、内部名、本机路径、内网地址、真凭据形态。

**第 1 条最关键**：先提交再删，git 历史里还是留着，`git log -p` 一翻就出来。

## 7. 上传服务默认只绑本机

局域网收件箱是好用的，但「默认对外」是错误的安全姿势。默认 `127.0.0.1`，
真要手机传图时显式 `--bind 0.0.0.0 --token 一次性口令`。

同理，`/stats` 这类接口不该回绝对路径。
